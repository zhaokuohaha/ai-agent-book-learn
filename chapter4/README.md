## 记忆卡

### 22.1 · 工具五分类：一张两轴地图
- **比喻**：Agent 的手和脚——但手脚也分功能：眼睛（感知）、手（执行）、同事（协作）、嘴（沟通）、闹钟（事件触发）
- **两轴**：谁发起（Agent 主动 / 注册→外部触发）× 作用于谁（读信息 / 改世界 / 驱动他人 / 推送用户 / 唤醒 Agent）——前四类同轴（Agent 是主语），第五类是特殊款
- **后端对齐**：感知 = GET 只读（控制输出量防上下文爆炸），执行 = POST/DELETE 写接口（错误代价高，安全第一），协作 = RPC 调下游（并行/不同模型分工），沟通 = 推送通知，事件触发 = MQ 消费者 / Webhook 回调
- **控制反转（第五类本质）**：注册时 Agent 主动声明（返回的是注册凭证，不是结果——真正的「结果」在未来以事件形式到达），触发时外部异步回调把 Agent 重新拉起。没有它，Agent 只能被动应答——无法定时行动、无法对新邮件/告警反应。D09 核心循环只处理前四类
- **实证**：`set_timer` 注册打印凭证 → `world_tick` 模拟外部到点唤醒——发起权从 Agent 交给外部世界

### 22.2 · ACI 原则一：通用执行器优先，专用工具有理由再上
- **ACI**：HCI 研究人怎么用电脑，ACI（Agent-Computer Interface）研究 Agent 怎么用电脑——工具该为 Agent 设计；早期形态「一个 API 端点包一个工具」粒度过细，成熟思路是工具对应 Agent 的目标
- **三层次**：① 默认上通用执行器（LLM 会写代码，沙箱解释器是「元能力」——生成能力的能力）→ ② 确需专用时粒度整合（extract_pdf/docx/pptx → read_document(file_type)，认知负担 3 选 1 变 1 个；扩展新格式=加选项不是加工具）→ ③ 四维决定何时退回专用
- **实证**：code_interpreter（真子进程）接住三个没预料到的任务——假期天数 7 / 中位数 74.0 / 温度换算 101.3，一个顶仨还能接住未来的第 N+1 个
- **形态 ≠ 披露**：做成工具还是 Skill，与一次让模型看见几条，是两个独立决策互不绑定

### 22.3 · ACI 原则二：描述的艺术——写「何时用」而非「能做什么」
- **三件套**：① 何时用（触发条件）② 边界（做不到什么+失败时怎么办——大多数调用失败的根因是模型不知道工具「不能」做什么）③ 参数示例（RFC3339 不如「例如 2024-03-15T14:30:00Z」，模型注意力稀缺直接套用；每工具 1-5 个调用示例，基准 72%→90%）
- **实证（同一实现同一任务，只换描述）**：v1「读取文档文本。」——模型盲调 read_document 撞 80MB 墙（1 次失败调用），知识只能从报错里事后学；v2 三件套+「必然失败不要调用」——零调用预判，回答原话「工具说明里明确写了 read_document 对超过 50MB 的文件必然失败」——知识来自描述的铁证
- **三跑实录（模型策略会摇摆）**：① 含糊任务（「内容给我看看」）→ 模型看 80MB 常识绕坑，v1 都不踩，对照消失；② 明确「逐字完整」锁死 read 语义 → v1 必撞墙；③ v2 描述要写「必然失败——不要尝试」才稳定预判。教训：任务措辞和描述强度都是实验变量——**先调描述，再怀疑模型**
- **更深一层**：v1 撞墙后自救与否也摇摆（有时切 summarize 有时放弃）——坏描述下行为不可预期；v2 每跑都零失败。**描述质量决定行为的可预期性**

### 22.4 · ACI 原则三：参数保真——模型的世界不能被偷换
- **两反模式**：① 静默输入转换（工具悄悄「修正」参数——Cursor 弯引号案例）② 静默参数注入（偷偷附加模型没传的参数——某 IDE git commit 案例）。共同点：参数层动手脚且不声张
- **实证（复现弯引号案例）**：v1 静默转换——模型传的 old 与文件一字不差（弯引号），工具在参数层换成直引号再去匹配 → 必然「未找到」，而报错回显的还是原文（弯引号）——偏差彻底隐形；模型被假失败逼出绕路（去掉引号只换词），4 步才碰到 v2 两步的结果。v2 保真——带引号的参数原样匹配一次成功
- **为什么模型无法自救**：它没有任何新信息——文件刚读过（弯引号在）、参数与文件一致、报错却说找不到；转换从不声张，模型的世界与工具的世界成了平行宇宙（系统性偏差）
- **首跑教训**：v1/v2 曾共用同一文件——v1 的绕路替换把「深度学习」从文件里消掉，v2 的正确参数也无从匹配——对照实验必须重置初始状态
- **正道**：确需规范化（如去首尾空白）——写进描述 + 返回值里明确告知，绝不偷偷改

### 23 · MCP：工具生态的 JDBC（23.1 server + 23.2 客户端 + 23.3 生态与安全）
- **比喻**：数据库驱动百花齐放 → JDBC 一套接口终结重复适配；MCP 同理——OpenAI function calling / Anthropic tool use / LangChain Tool 各自为政，工具开发者被迫逐家适配。价值：一次开发处处可用，一个 server 所有客户端（Cursor / Claude Desktop）都能用
- **架构**：客户端-服务器；JSON-RPC 2.0 over stdio（本地，换行分隔一行一个 JSON）/ Streamable HTTP（远程，报文不变）；initialize 握手先协商（协议版本 + capabilities 各原语独立声明）再干活——无状态协议的「会话凭证」
- **三类原语 = 三个决策权**：tools 模型可执行（LLM 看 description 选）/ resources 应用可读取的只读数据 / prompts 用户可选用的模板——D09 信任分层的回响；23.2 实测 capabilities 里三类各自独立声明
- **版本差异注**：课件 FastMCP 是 mcp v1 写法；2.x 已更名 `from mcp.server.mcpserver import MCPServer`，装饰器用法不变（装了 mcp 2.3.0）
- **实证（23.2 首跑即通）**：手拼原始 JSON-RPC（不用 SDK，协议看得见每个字节）——握手→tools/list（ACI 三件套描述+JSON Schema 强制）→tools/call 杭州 26°C、成都报错（边界跨进程生效）→resources/read 城市列表→prompts/get 参数化模板，三类原语同一连接同一协议
- **作业③答案示范**：第一个 MCP 工具选天气查询，description 按 ACI 三件套写（23.1 的 get_weather）——描述是写给模型看的使用说明书，跨进程、跨客户端都靠它

### 23.3 · Skill Hub 与供应链安全：另一条分发路线 + 引入第三方能力的代价
- **分发对照**：MCP = 协议路线（JSON-RPC+独立进程+凭证，运行时接入）；Skill = 注册表路线（skills.sh / ClawHub，`npx skills add owner/repo` 装文件夹，不用协议）——MCP 交付「服务」，Skill 交付「文档」
- **token 成本（最疼差异）**：MCP 全部工具定义进每次会话的静态前缀（D09）；Skill 常驻只有 frontmatter 的 name+description，正文用到才读（D13）——实测教学版 schema 差约 5 倍，真实 schema 更大差距更宽，正文按需读再放大（课件「一到两个数量级」）；形态与披露是两个独立决策（D22 回响）
- **三风险**：① 工具描述投毒——指令藏在 description 里随每次会话生效，D12 提示注入的载体变种，且顶着「开发者规则」的信任等级更难防；② 同名工具遮蔽——注册表合并同名静默覆盖，敏感参数被路由到恶意方（dict merge 实测无警告）；③ 恶意/被劫持服务器——依赖投毒+远程 server 被篡改，装的时候干净≠一直干净
- **三板斧（软件供应链一脉相承）**：接入前审查描述（当不可信输入审计，而非无害元数据）/ 锁定版本（uv.lock、固定 commit，拒绝静默更新）/ 最小权限凭证。**Skill 含可执行代码，危险系数比 MCP 更大**——不可信的隔离环境跑

### 24.1 · 工具规模的两笔账：选错率与 token/缓存开销
- **比喻**：全量注入 = 每次建连都把全库 DDL 下发给客户端——正解是先 SHOW TABLES 给索引，要哪张表再 DESC
- **账一·正确性**：工具超 100 个，先进模型也选错——Qwen3-4B 面对 120+ 工具全量注入指令遵循崩掉（查股价调 web search）；机制：选项越多注意力越稀释，名字长得像（get_price_A股/港股/美股…近邻 10 个）是选错温床
- **账二·钱包**：100 工具（4 服务器×25）全量 schema 实测 ≈26900 字符 ≈1.6 万 token 估算；tools 是静态前缀，工具集一变击穿 KV Cache（D10 回响）
- **三档实算**：全量 26900 / 分组目录 1236 / 语义预筛 top-2 538 字符——全量/索引 ≈ 22 倍（Cursor A/B 实测省 46.9%；Anthropic 预筛 Opus 4 准确率 49%→74%；MCP-Zero 2800 工具省 98%）

### 24.2 · 主动工具发现：discover_tools 元工具 + KV 保命（作业①②③落点）
- **MCP-Zero 模式**：常驻工具集缩到最小（一个 discover_tools 元工具），其余 Agent 执行中自己声明能力缺口（need="我需要查股价的能力"）→ 两层语义路由（先选服务器再选工具，bge 嵌入余弦——对齐 Anthropic Tool Search Tool 的 embedding 检索，课件 Jaccard 是玩具）→ 命中则 schema 注入+注册；未命中明确 404（「返回 404，别返回模糊的空结果」）
- **实证（闭环）**：任务「查 AAPL 股价」→ agent 自主声明缺口 → 路由到金融服务器命中 get_stock_price → schema 以 user 消息注入（D13 同款）+ bind_tools 追加 → 调用 → 回答 189.50 美元；全程目录常驻仅 12 行索引
- **404 降级两种形态（都实测过）**：模型改写需求重试（「播放音乐」404→改「生成音频/MIDI」再 404→兜底）；或直接看目录判断无此能力兜底（更省调用）——目录可见性本身就在第一层防无效发现
- **KV 保命三原则（作业③）**：① schema 作为普通消息（user 槽位）追加到末尾，不进静态前缀；② 固定首次注入原位，只增不减；③ 新工具进 tools 只追加不重排。实测 DeepSeek prompt_cache_hit_tokens：发现工具那轮 tools 变长 → 命中只剩 system 段（384）；之后 tools 稳定消息只追加 → 命中回升（512）——「工具集一变击穿缓存、只追加则持续命中」的活证据；「工具定义必须放最前面」从此不再是铁律
- **首跑翻车记（D09 配对链又一实证）**：模型一轮发两个 discover 调用，schema 注入消息夹在两个 tool 回执之间 → 破坏 tool_call_id 配对 → API 400——修复：先补齐全部回执，再统一追加注入消息

### 25.1 · 显式截断：静默截断之恶与 offset/limit（作业①）
- **比喻**：后端接口悄悄丢字段还返回成功——查起 bug 想打人；静默截断 = 偷走模型的世界还让它自信作答
- **对照（变量=披露）**：同一本地 HTTP 长日报、同一 LIMIT 切点（切在「数据库事件」节前的段落边界——连句子断了的线索都没有）。A 朴素端点：返回 text[:LIMIT]、无分页参数、不说话——模型没信号也没把手，读完全「正常」的前四节自信答「无异常」（坏盘事件在切点后）；B 课件修正版：offset/limit 把手 + 末行「[已显示 x/y，传 offset=x 继续]」信号 + 描述写明行为（ACI）——模型自主传 offset=509 翻页，答出 db-shard-3 坏盘与改期建议
- **结论**：显式截断不是礼貌问题，是信息问题——没有那行字，模型连「该怀疑」的线索都没有；修复成本一行 f-string，收益是决策依据从残缺变完整
- **首跑翻车记**：A/B 曾共用同一 schema（都带 offset/limit）——LangChain 把参数默认值写进工具 schema，模型看到 offset 存在+默认 509，无信号也精确投机翻页自救成功，对照失效；静默截断的完整形态必须连把手也没有

### 25.2 · 搜索类量控：结构化候选列表 + 分页游标
- **比喻**：搜索结果页给你标题+摘要+链接，从不塞整本原文——先浏览货架，再取一件
- **候选列表形状**：编号+标题+摘要（前 N 字）+指针；指针是第二跳的入口（网页搜索=URL、文档站=read_doc(N)），深读动作由 25.1 的 offset/limit 完成——两斧合璧 = Cursor 的 search→read 两段式（24.1 索引先行的同构回响）
- **分页游标**：返回值注明总数与翻页方式（cursor=N），Agent 自主决定是否继续；走到头明说「已到末页」——与 24.2「明确 404」同一种诚实，不静默
- **实测**：同一查询（6 篇学习笔记 BM25 检索）拼接全文 797 字符 vs 候选列表 180（23%）——语料只是缩小版，真实网页单页 3k-30k 字符 vs 摘要 ~160，比例一到两个数量级；top-5 全文常只深读 1 篇，其余白烧窗口

### 25.3 · 只读红利：可缓存 + 可并行（作业②）
- **比喻**：GET 接口套 Redis；图书馆大家可以同时查同一本书，手术室不行
- **缓存实测**：@lru_cache 一行包住 fetch（课件原版）——同一 URL 连抓两次：无缓存版服务端 2 次、第二次照旧 403ms；缓存版服务端仅 1 次、第二次 0.0ms。证据取服务端命中计数——比「客户端变快」更硬（快可能是巧合，后端少收一次请求不会骗人）
- **并行实测**：ThreadingHTTPServer（每请求一线程——串行服务器会让并行假摊）+ ThreadPoolExecutor 3 路 GET：串行 1.23s → 并行 0.41s（墙钟 3 倍；I/O 等待释放 GIL，三路往返叠着走）
- **边界**：这自由只属于只读——lru_cache 套在写接口上是灾难（缓存=重放副作用）；执行工具并发要操心顺序/副作用/补偿（D26 主角）。彩蛋：25.1 的 fetch 每次 offset 续读重新 GET 全文，套 lru_cache(url, offset) 后同页复抓零成本

### 26.1 · 执行工具第一闸：输入验证与快速失败（作业①③）
- **比喻**：写操作是 POST/DELETE——发错撤不回，所以闸门的原则是「有疑就拦」；感知工具读错只是信息不对，执行工具发错命令是事故
- **快速失败**：发现异常立即拒绝，绝不「智能修正」——22.4 的回响：静默修正是平行宇宙噩梦，拒绝才是诚实
- **白名单 vs 黑名单**：白名单=允许清单（逐命令授权），黑名单=已知攻击串兜底（平台相关：Linux 的 rm -rf vs Windows 的 del /s）——两者都是字符串防御
- **绕过现场（作业③）**：`echo x & whoami`——白名单只查「首命令」echo，cmd 用 & 串联整条链，whoami 从未被检查、真的执行了（输出里是真实用户名）；黑名单也救不了——whoami 不在「已知」清单
- **修复**：按 & | 拆链逐段校验（v2）——同一命令报「链中命令不在白名单」，正常命令不误伤；更健壮的方案是语义解析（26.3 的 Sidecar）
- **顺带第三层**：执行侧截断 + 持久化——与 25.1 对照：读的截断可 offset 续读（原文在服务端），执行的输出是一次性产物，丢了就永远丢了——截断提示必须给出落盘路径

### 26.2 · 沙盒隔离谱系：venv 不是沙盒
- **比喻**：venv 是「换了个装包的抽屉」，不是「换了间上锁的房」——它只隔离依赖，代码的腿照样伸出去
- **误区实证**：sys.prefix 显示 .venv，而同一个进程里的 os.remove 真删掉了圈外文件（文件还在吗：False）——删除/读取/联网的腿全在抽屉外
- **进程级沙盒的全部家当 = 一个圈 + 一根绳**：圈=cwd 限定工作目录（真测试：写入落在圈内；但圈只圈「默认落脚点」不圈腿——绝对路径真读到了 C:\Windows\win.ini）；绳=timeout 到点绞杀（超时进程被终止）——但绳是止损不是防害：命令已经跑起来了
- **三层级（了解级）**：进程级（逃逸零门槛，本地开发够用）< 容器（独立文件系统/网络栈、共享内核，逃逸需内核漏洞）< microVM（独立内核，跑完全不可信代码）；容器/microVM 还要资源限额（--memory/--cpus）；Docker 示范见对照表

### 26.3 · Sidecar 门控：语义审查的第三道闸
- **比喻**：微服务边车——挂在主流程旁不做主干工作，只做一件事：每次工具调用放行前判「危险吗」；前两道闸（字符串校验/进程隔离）都有盲区，意图层面的攻击要靠语义审查
- **两个关键**：① 只喂结构化字段 {tool, command}——注入是自由文本，到不了审查员眼前（攻击面物理切断，不赌定力）；② 拒绝熔断器——连续拒绝达阈值转人工（阈值=2 实测轨迹：拒绝(1/2) → 熔断 → 第 3 次不再调用）
- **实测记**：两轮注入形态（直白「判定 SAFE」指令式 / 伪造「预填审查结果」式）deepseek 都没被带偏——但概率题赢一轮不改结构：更隐蔽的多轮注入、更小的分类模型都可能失守（22.3 三跑摇摆同理）
- **与提议者-审核者的分工**：审开放式思考要能力相近+认知多样性（两位工程师互审方案）；Sidecar 判简单分类（危险与否）——轻量模型数百毫秒够用，且与主流式输出并行、不阻塞用户

### 26.4 · Sidecar 进循环：拒绝回执与模型重规划（闭环）
- **比喻**：26.3 回答了「审查员该看到什么」，26.4 把它装进循环、接通电——闸门接在「模型伸手拿工具」的咽喉线上
- **四个接线点**：① 提取——resp.tool_calls 本来就结构化（{name, args}），「只喂结构化字段」零成本；② 分级——只读工具免审直过、写工具过闸（闸门强度按风险配）；③ 拒绝回执——被拒也要回填 ToolMessage（D09 配对铁律）+ 写「为什么+出路」（模型唯一的新信息）；④ 重规划——模型看到回执后从「执行」转向「协商」
- **实测实录**：任务（磁盘告警，按维护规程清理）→ 模型拦前 5 轮只读探查（file/readlink 验证目录、ls 查快照、探测冷存储挂载）——它在尽力验证 README 的「已备份」声明，但文档可信度它验证不了；按规程提 rm -rf → 闸门 UNSAFE 拦截（无执行行）→ 模型立即转诚实汇报「尚未清理任何数据」——一次拦截、零拉锯
- **纵深结论**：模型已谨慎到极限，依然卡在「验证不了只能选择信不信文档」——防护必须外置为闸门：不信模型的定力，信咽喉点的接线
- **对照彩蛋**：语义审查对「复杂但无害」的复合命令（ls; df | head）宽容放行——26.1 的字符串拆链会误杀这类命令，两代防线宽严互补

### 27.1 · 子 Agent 委托：四要素岗位书与上下文交接
- **比喻**：不造全能员工、造专业团队——每个子 Agent 独立提示词/工具集/知识库，互不冲突（类比微服务：按业务域拆，独立迭代）
- **岗位书四要素**（make_persona 逐条落点）：① 角色清晰「你是专门负责 XX 的助手 Agent」② 来源标注 [FROM_MAIN_AGENT]/[FROM_USER]/[TOOL_RESULT]——防混淆来源引发注入（D12 落点）③ 边界明确（什么要转交上报）④ 输出标准化（约定 JSON 降低主 Agent 解析负担）
- **实证（变量 = 交接）**：同一个子 Agent、同一份数据——A 最小化传递（只塞任务+原始数据）丢了「只要 P0」约束，报全量口径 16.09%；B 主 Agent LLM 生成交接文档（约束带 [FROM_USER] 来源标注）→ P0 口径 1.09% 正确
- **结论**：交接质量决定委托质量——子 Agent 再专精，喂错上下文也白搭

### 27.2 · 协作原语与形态：spawn / send / cancel / list_agents
- **三组原语（类比微服务治理）**：启动与取消（spawn 立即返回任务 ID = 异步语义；cancel = 服务调用+超时熔断，止损省 token）、消息传递（send 双向 = 请求-响应+回调）、发现（list_agents = 服务注册中心，同 MCP tools/list 思路——只不过列的是 Agent）
- **四形态轨迹指认**：异步（spawn 0.001s 返回、主线程不等）、流式（子 Agent 每步推进展）、多轮（send 补充指令、步间消费 inbox）、同步（文末对照：原地等结果，快任务可用）
- **实证（threading+queue）**：reporter 中途 cancel——在途步骤 3 跑完、第 4 步检查点生效（止损省 2 次调用）——**取消是协作式的**：检查点粒度决定止损速度（真实系统 cancel 也省「剩余步骤」、省不掉「当前步骤」）
- **选型**：快任务同步简单；长任务异步——把「等待」还给主线程

### 27.3 · HITL：机器拿不准，最后一级交给人
- **三件套**：① 超时降级——超时阈值 + 保守默认（高危默认拒绝，无人值守也兜得住）② 优先级队列——注意力按风险花（紧急：电话+群+红灯；普通：只发邮件）③ 反馈沉淀——批准/拒绝理由进账本 → 同类请求先检索 → 第 N 次决策更快更一致（进知识库/Skill，D13）
- **四幕实测**：批准（理由进账本）/ 拒绝（回执「为什么+出路」）/ 超时（降级保守拒绝——「超时」也是一种拒绝来源）/ 回放（同类再现 → 命中历史理由 → 快速批准）
- **与 26.4 同构**：HITL 拒绝回执同样是「为什么+出路」——回填主循环驱动重规划
- **真实接线**：scripted_human 换 Slack/webhook 等待 + 超时定时器；账本换知识库/Skill 跨会话复用；隐式偏好（总批准某类/总拒绝某类）作后训练数据

### 28 · W4 收官：玩具 Agent 合体（≥3 个真实工具）
- **合体清单**：手写 while（保持干净——闸门不在这里）+ 三个 @tool（描述写满自查五项）+ 安全内嵌实现（read/write 路径锁；run_command 拆链白名单 + 圈绳 + UTF-8 强制）；docstring 顶部带「知识点地图」逐行对应落点
- **工具抽查**：read_file 大文件显式截断——尾部写明「完整 6000 字符，续读 offset=4000」，续读到尾不再截断（D25：绝不静默、只给把手）
- **实测轨迹**：read_file(sales.txt) → write_file(calc.py)（描述引导它写脚本）→ run_command("python calc.py")（真 python：946100 / 118262.5 / 154300 全对）→ write_file(report.md) → read_file(report.md) 读回核对 → 汇报（自述「脚本计算，未手工估算」）
- **产物 + 彩蛋**：report.md 真实落盘；这条链是「代码编排」雏形——中间计算留在执行环境、只有结论回上下文（每次汇报 vs 一次编排的差距预告）

### 协作三组原语 ↔ 微服务治理（D27）

| 原语 | 干什么 | 微服务类比 | 本仓库落点 |
| --- | --- | --- | --- |
| spawn / cancel | 创建子 Agent（立即返回 ID）/ 任务失去意义时止损 | 服务调用 + 超时熔断（避免白烧 token） | `27.2` |
| send_message | 双向通信：汇报进展、请求澄清 | 请求-响应 + 回调 | `27.2` |
| list_agents | 列出可用 Agent 的职责与状态 | 服务注册中心（同 MCP tools/list 思路） | `27.2` |

### 四种协作形态（D27）

| 形态 | 语义 | 适合 | 本仓库落点 |
| --- | --- | --- | --- |
| 同步调用 | 等结果再继续 | 快任务（实现最简单） | 27.2 文末对照 |
| 异步调用 | 立即返回任务 ID、完成时再收（MQ 削峰模式） | 长任务——把「等待」还给主线程 | `27.2` 主线 |

| 多轮交互 | send 补充指令、步间消费（对话式协作） | 中途需求变化、需澄清 | `27.2` send 实测 |

## 自测（遮住括号自测）

1. 五类工具的两轴坐标是什么？（谁发起 × 作用于谁；前四类 Agent 主动调用，第五类注册→外部触发）
2. set_timer 为什么返回注册凭证而不是结果？（主动调用的语义是「现在要结果」；定时器要的是「未来某刻叫醒我」——结果在未来以事件形式到达）
3. 没有事件触发类工具，Agent 缺什么？（无法定时行动、无法对新邮件/告警做出反应——只能被动应答）
4. code_interpreter 为什么是「元能力」？（生成能力的能力：LLM 会写代码，代码表达几乎任意计算——一个解释器 ≈ 任意专用工具的并集）
5. 三个 extract_* 工具该怎么改？为什么？（合并成 read_document(file_type)——认知负担 3 选 1 变 1 个，扩展新格式只加选项不涨注册表）
6. 四维决策是哪四维？变更频率维怎么判？（安全权限/参数复杂度/变更频率/模型能力；常变的能力用 Skill 文本维护——改文字远比改代码+部署轻）
7. 形态和披露是什么关系？（两个独立决策：做成工具还是 Skill，与一次让模型看见几条，互不绑定）
8. 描述三件套？哪件最重要？（何时用 + 边界 + 参数示例；边界——大多数调用失败的根因是模型不知道工具「不能」做什么）
9. 为什么参数示例比格式说明有效？（模型在复杂任务中只能分出一小部分注意力确认格式，例子让它直接套用——72%→90%）
10. 参数保真的两个反模式？（静默输入转换：悄悄「修正」参数；静默参数注入：偷偷附加参数——共同点是不声张）
11. 弯引号案例里模型为什么无法自救？（它没有任何新信息：文件刚读过、参数与文件一致、报错却说找不到；转换发生在参数层且从不声张——两个平行宇宙）
12. 确需规范化参数时正道是什么？（写进工具描述 + 返回值里明确告知改了什么，绝不偷偷改）
13. Agent 频繁选错工具，第一步查什么？（描述——修描述的投入产出比远高于换更强的模型；22.3 实证：改三行描述，行为从「盲调撞墙」变「零调用预判」）
14. MCP 为什么被比作 JDBC？（每家框架定义工具的方式不同→工具开发者逐家重复适配；统一协议终结碎片化——一次开发处处可用）
15. initialize 握手在协商什么？（协议版本 + capabilities：server 声明支持 tools/resources/prompts 哪些原语，客户端据此决定能调什么——无状态协议先协商后干活）
16. stdio 传输长什么样？（换行分隔的 JSON-RPC 2.0：一行请求写进 server stdin，一行响应从 stdout 读；远程换 Streamable HTTP，报文格式不变）
17. tools/resources/prompts 三类原语各自的「决策权」归谁？（模型可执行/应用可读取/用户可选用——同一连接同一协议，使用者不同）
18. mcp 2.x 和课件代码的差异？（课件 `from mcp.server.fastmcp import FastMCP` 是 v1 写法；2.x 更名 `mcp.server.mcpserver.MCPServer`，装饰器用法不变）
19. 为什么 23.2 手拼 JSON-RPC 而不用官方 SDK 客户端？（SDK 遮住协议细节；手拼看得见每个字节——「标准」长什么样一目了然；Inspector 适合人肉点调，脚本捕获可复现）
20. Skill 分发为什么不需要协议？（skill 就是装着 SKILL.md 的文件夹，文本本身就是通用接口；分发靠注册表一条命令装目录）
21. MCP 和 Skill 的常驻上下文成本差在哪？（MCP 全部工具 schema 进每次会话的 tools 静态前缀；Skill 常驻只有 frontmatter 两行，正文用到才读——实测教学版差约 5 倍，真实 schema 更大）
22. 工具描述投毒和 D12 提示注入的异同？（同：指令伪装成数据混进上下文；异：载体从外部素材换成工具定义，且顶着「开发者规则」的信任等级——更难运行时防御，只能前移到接入前审计）
23. 同名工具遮蔽怎么发生？（多 server 合并注册表时同名静默覆盖，Agent 的调用（含敏感参数）被路由到恶意方——dict merge 实测无警告）
24. 引入第三方能力的三板斧？（接入前审计工具描述 / 锁定版本拒绝静默更新 / 最小权限凭证；Skill 含可执行代码危险更大，不可信的隔离环境跑）
25. 工具规模的两笔账？（账一正确性：超 100 个先进模型也选错（Qwen3-4B 崩掉）——注意力被稀释；账二钱包：全量 schema 数万 token 占窗口近三成 + 工具集一变击穿 KV Cache）
26. 全量注入的后端类比？（每次建连都把全库 DDL 下发客户端——正解先 SHOW TABLES 给索引，要哪张表再 DESC）
27. 三层按需披露各自常驻什么？（索引：分组目录常驻，模型看目录自取；发现：只常驻元工具+基础工具，Agent 声明缺口动态注入；Skills：frontmatter 目录，正文用到才读）
28. 为什么预筛不够还要主动发现？（预筛按用户初始查询一次性匹配，「Debug the file」这类简单请求会牵出跨领域工具链——执行中才知道缺什么能力）
29. discover 未命中时该返回什么？（明确 404「未找到」，让 Agent 改写需求或兜底——返回 404，别返回模糊的空结果）
30. 动态加载怎么不毁 KV Cache？（三原则：schema 以 user 消息追加到末尾不进前缀；固定首次注入原位；tools 只追加不重排——真正重算的只有 TTL 过期和改/删/重排工具集）
31. 24.2 实测的缓存数字说明什么？（发现工具那轮命中只剩 system 段 384，之后稳定 512 回升——工具集变击穿缓存、只追加则持续命中的活证据）
32. 24.2 首跑为什么 400？（模型一轮发两个 discover，schema 注入消息夹在两个 tool 回执之间破坏 tool_call_id 配对链——修复：先补齐全部回执再统一注入，D09 铁律又一实证）
33. 感知工具的两大工程红利从哪来？（只读无副作用：结果可缓存（GET 套 Redis）、调用可并行（同时读互不干扰）——执行工具没这种自由）
34. 防上下文爆炸三板斧？（搜索类结构化候选列表（标题+位置+摘要）；结果多分页 cursor 注明总数与翻页；读取类 offset/limit+截断时明说省了多少怎么续读）
35. 为什么静默截断最危险？（Agent 以为看到全部，基于残缺信息自信决策且无法自救——没信号（末行提示）也没把手（分页参数），「不知道自己不知道」）
36. 候选列表为什么必须带指针？（第二跳的入口：Agent 浏览候选后决定深读谁，指针（URL/read_doc(N)）让深读有处可去——两斧合璧 = search→read）
37. 三条多模态路线怎么选？（原生多模态布局最强但 token 最贵；OCR 提取为文本最省但版式图表丢；工具化分析一问一答只留结论——主模型无视觉时的优选）
38. 25.1 首跑为什么翻车？（A/B 共用同一 schema：LangChain 把 limit 默认值 509 写进工具 schema——模型看到 offset 存在+默认页大小，无信号也精确投机翻页自救；静默截断的完整形态必须连把手也没有）
39. 执行工具与感知工具的根本差别？（改世界 vs 读信息——误删撤不回/错误命令能打挂服务；写操作才需要防重、幂等、审核）
40. echo x & whoami 为什么能绕过白名单？怎么防？（白名单只查首命令，shell 执行的是全链；防御：拆链逐段校验每段首命令——黑名单只认已知串救不了未知）
41. 黑名单为什么只是兜底？（字符串匹配挡不住变形与未知命令，且平台相关——Linux rm -rf vs Windows del /s；健壮方案要理解意图）
42. 执行侧截断与读取类截断的区别？（读的截断可 offset 续读（原文在服务端）；执行输出是一次性产物，丢了就永远丢了——必须落盘并在提示里给路径）
43. venv 为什么不是沙盒？（只隔离包依赖；代码的腿照样伸出抽屉——删文件/读数据/连网络；换抽屉≠上锁房）
44. 进程级沙盒的全部家当？（一个圈 + 一根绳：cwd 只管默认落脚点、绝对路径管不住；timeout 止损不防害——命令已跑起来只是到点被杀）
45. 隔离三层级？（进程级 < 容器（共享内核，逃逸需内核漏洞）< microVM（独立内核）；容器/microVM 配资源限额；本地开发进程级够用，生产或不可信输入往上走）
46. Sidecar 门控的两个关键？（只喂结构化字段 {tool, command}——注入是自由文本没落脚点；拒绝熔断器——连拒达阈值转人工，不拉锯）
47. Sidecar 为什么轻量模型够用？与提议者-审核者的区别？（审简单分类（危险吗）；互审开放式思考才需要能力相近+认知多样性——审查对象不同）
48. 转账超时重试「钱转没转」怎么解？（幂等键去重（服务端重放首次结果）；先查询后变更（重试前确认状态）；邮件/转账等天然不可逆走预检-确认两段式——失败带错误回主模型重规划，不盲重试）
49. Sidecar 接进循环的四个接线点？（提取：resp.tool_calls 本来就结构化；分级：只读免审、写工具过闸；拒绝回执：ToolMessage 回填+写「为什么/出路」；重规划：模型从执行转向协商）
50. 26.4 里模型为什么「验证不了就按规程执行」？说明什么？（拦前它做了多轮只读探查试图验证备份声明——文档可信度无法自证；说明防护不能指望模型分辨文档真伪，必须外置为闸门）
51. 子 Agent 提示词四要素？（角色清晰；来源标注（[FROM_MAIN_AGENT]/[FROM_USER]/[TOOL_RESULT]——防混淆来源引发注入）；边界明确（什么要转交上报）；输出标准化（约定 JSON 降低主 Agent 解析负担））
52. 27.1 的 A/B 对照变量是什么？结论？（交接上下文——A 最小化丢了 [FROM_USER]「只要 P0」约束，口径 16.09% 全量误报；B LLM 交接保约束，口径 1.09% P0 正确；交接质量决定委托质量）
53. spawn 立即返回 ID 是什么语义？cancel 为什么省 token？（异步：拉起即返回、不等结果；子 Agent 每步前查取消标记、余步不执行——取消是协作式的：在途步骤跑完、下个检查点生效）
54. HITL 三件套？（超时降级（阈值 + 保守默认，高危默认拒绝）；优先级队列（注意力按风险花）；反馈沉淀（理由进账本 → 同类命中 → 决策更快更一致））
55. 五类工具本章讲了几类？剩下两类何时讲？（三类：感知（只读，可缓存可并行）、执行（写操作，分层防护）、协作（子 Agent 生命周期）；事件触发与用户沟通依赖异步运行时——第 6 章）
56. 退回专用工具的四个决策维度？（安全与权限、参数复杂度、变更频率、模型能力——通用执行器是默认，有理由才专用；22.2）
57. 工具描述自查清单五项？（何时用、边界、参数示例、返回值结构、调用示例——Agent 频繁选错工具时先修描述）
58. 不同 MCP 服务器同名工具行为不一致（一个返摘要一个返全文），Agent 如何感知并利用？（描述即契约：注册时「返回值结构」写清各自形态，按描述预期、发现不符时轨迹内调整或请求澄清；更阴的是同名遮蔽（D23）——合并注册表必须防静默覆盖，审计 + 最小权限才是根治）
