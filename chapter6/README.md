## 记忆卡

### 36 · 模态与触发时机：能力坐标系的两条新轴
- **比喻**：观察空间×动作空间 = API 的出入参 schema——入参类型越丰富能处理的问题越广，出参能力越强能触达的世界越大；模型是那个「处理函数」，**函数不改，改 signature 照样解锁新场景**（常见误区：以为能力提升只能靠换更强的模型——多数产品级提升来自扩展 I/O，像后端优化先改架构而不是先换机器）
- **前五章挂回坐标系**：上下文工程/记忆/RAG 扩观察空间的内容；工具/代码生成扩动作空间的内容——W6 沿「模态」「时机」两轴扩展
- **模态 = 形式维度**：观察从只读文本到语音/屏幕/物理传感器；动作从只输出 token 到发声/点击/驱动关节；类比接口协议升级（JSON 文本 → 音频流/图像帧/控制信号）——协议一变，编解码、带宽、时序全要跟着改（所以本章每种模态单独一天）
- **触发时机 = 节奏维度**：观察是主动取（轮询）还是世界推（事件驱动）；动作是回合内做完还是跨回合、可中断、可被抢占；类比轮询 vs Webhook/消息队列、同步 RPC vs 异步任务——前五章的 Agent 是同步接口（请求进来处理完才返回，期间不接新请求），本章改造成事件驱动的服务
- **为什么时机轴先走**：纯架构问题不涉及新 I/O——D37 异步的模态完全没变（还是文本），只变节奏；这是从回合制世界迈出的最小一步

### 36 · 核心论断：回合制是交互约定，不是环境性质
- **论断**：默认「用户说完 → Agent 想一段 → 答一句，期间世界静止」——这个前提自然到很少被当成假设写出来，但它只是早期工具调用接口的组织方式（提问后跟回答、工具结果补齐后才继续推理）；**环境是连续的、并发的，回合制只是给接口降了速**
- **为什么必须打破**：邮件在 Agent 思考时到达、用户在它说到一半时插话、页面在两次截图之间变了样、杯子在机械臂伸手途中被碰倒——真实世界不等人
- **两个常见误区**：① 把 API 的同步轮次当成物理限制——截至 2026 年 9 月 GPT-6 Astra 已支持原生异步工具调用和回合中途追加用户指令；② 以为代码里用了 asyncio 就具备原生异步能力——事件来源、工具生命周期、结果归属仍要应用层自己管理

### 36.1 · 两种世界观的最小现场（回合制 vs 事件驱动）
- **实证（同一确定性事件流：0.0 定时任务 / 0.2 新邮件 / 0.5 CI 失败 / 1.2 收尾）**：A 回合制——CI 延迟 0.5s（邮件回合 0.2~0.7s 把它压到 1.0s 才开始处理）、思考期间邮件堆积、总时长 1.5s；B 事件驱动——CI 延迟 0.0s（到达即抢占分块中的邮件处理）、摘要任务发起即挂句柄不阻塞、1.2s 收尾事件关闭、总时长 1.2s——**同一世界两种命运**
- **B 版三个机制（D37 的伏笔）**：队列唤醒（q.get 阻塞等待不忙轮询）+ 高紧急抢占（分块执行、块间让位——课件机器人档「动作分块·可被抢占」的最小形态）+ 动作跨回合（发起挂句柄，靠收尾事件 close——任务句柄雏形）
- **简化注**：抢占用「块间查队列」模拟（sleep 不可中断）——生产用 asyncio.cancel/线程中断；事件源生产上是消息队列/webhook 非脚本线程

### 37 · 异步与事件驱动：当世界主动找上门
- **比喻**：同步 Agent 是只会排队的柜台（处理完一个才叫下一个——要么等后台任务才能对话，要么等对话结束才能接新事件）；异步 Agent 是灵活的秘书（多待办按紧急程度切换，做到一半可暂停）——BIO→NIO 的切换；把所有输入（用户消息/工具返回/外部回调/定时触发）统一建模为事件流，push 取代轮询
- **三类事件触发工具**：set_timer（一次性「下周一十点致电」/循环「每小时巡检」——对方不推送的服务只能定时反复查）、monitor_shell（长命令监控新增输出或关键词——不能烧 token 盯着看也不能跑完才发现卡死）、connect_channel（邮件/API 回调/IM 实时推送——PineClaw 心跳轮询早等凉了）；设计要点：触发条件带过滤（无关事件不唤醒）、载荷自带上下文（减少二次查询）
- **结构化事件四维**（来源/渠道/内容/上下文）——统一 schema 后三策略才有统一前提（Kafka 统一信封）；**来源维度是注入防线**：只有来源清晰才不会把工具结果里藏的指令当成用户指令
- **三策略（紧急度路由）**：取消式（紧急：提前制造安全点——取消流式→清空队列→全部事件追加→立即重估）、队列式（常规：攒到安全点批量追加省往返，如等搜索时用户补「只看最近一个月」）、并行式（独立轻量：旁路小会话即答，结果标记后归档主轨迹）；**路由器用轻量分类 LLM 非硬编码**（37.1 实证）
- **占位符规则**：打断时为未完成工具生成占位 ToolMessage 维持配对合法，**不伪造成功**；「收到停止不撤销已发生的动作」——被打断的查询后台跑完迟到（已提交事务不自动回滚），结果仍归属
- **任务句柄 initiate_xxx**：启动与完成解耦——工具命名就是给模型的 API 文档（initiate 前缀暗示「发起而非完成」），立即返回 task_id，结果以事件到达；submit/job_id/Future 同构
- **误区与边界**：asyncio ≠ 原生异步（应用层并发≠模型层异步——事件来源/工具生命周期/结果归属仍要应用层管）；GPT-6 Astra 已支持原生异步工具调用+回合中途引导，但三检查（结果归属/恢复控制/多条更新综合）仍是应用层责任
- **沟通工具与虚拟身份（速览）**：专门工具发消息（双方随时互发/按紧急度推送=活人感，通知即召回）；独立虚拟身份+虚拟电脑隔离（最小权限 service account 而非共享 root）；必须本人登录走 VNC 远程桌面 HITL（亲眼看到 Agent 在做什么）

### 37.1 / 37.2 · 路由与兼容实验
- **37.1（关键词 5/7 vs LLM 语义 6/7）**：棺材钉一（「先别继续了，马上」无「停」字，关键词版误入队）语义路由判对；棺材钉二（「别停在半路，继续跑完」含「停」）模型判 cancel 且理由自洽（「立即处理继续指令」）——语义边界如实呈现（22.3 三跑摇摆同款）
- **37.2 不编造双份实证**：幕一（2 个并行 search 被打断→逐个占位符→模型「没有返回任何结果……我不会凭记忆硬写」→迟到结果恢复总结）；幕二（3 个并行 initiate 拿动态句柄 t1/t2/t3→「都还在运行中，我不能凭记忆先给结论」→结果事件到达综合）——可靠性三检查之首（结果归属）的正面证据
- **首跑翻车**：deepseek 常并行发多个 tool_call，只配一个 ToolMessage → 下一轮 invoke 400（「配对规约是硬约束」）；修为 drain 逐个配对

### 38 · 语音：最自然的人机接口（三范式 + 快慢分离）
- **为什么要专门讲语音**：说话速度约为打字 4 倍且不占双手视线；前五章的 Agent 是「请求-响应」式 Web 服务，语音 Agent 是**长连接实时系统**——边听边想边说、随时可能被中途打断；第二方向：Agent 代用户对外打电话（代客协商账单）是对外交互不只是人机对话
- **范式一：级联流水线**：VAD→ASR→LLM→TTS 四级串联（同步 RPC 调用链/微服务同构）——可独立优化替换调试；代价也同构：每级延迟串行累积 + 接口处丢副语言信息（情绪/犹豫/附和声）
- **流式四手段**（把完全串行改成边到边流水线）：ASR 边听边转（转写与说话重叠）/LLM 推测执行（临时转录先想，一致不重调不一致取消重算——CPU 分支预测思想）/LLM 分段输出（首段可播文本立即交 TTS）/TTS 增量合成（音频块持续返回，生成合成播放重叠）；更进一步：流式听觉模型把识别+部分理解放进同一模型，输出声学事件标记（speak_start/emotion/laugh）——能感知犹豫和打断
- **范式二：端到端 Omni**：同一模型直接听音频生成语音，无中间文本——延迟更低+副语言保留（能听停顿情绪、能唱歌）；代价：训练贵、模块不可独立替换（四个微服务合并成单体的同构取舍）；仍是轮流说话靠 VAD——报电话号码的中途停顿仍可能被误判说完
- **范式三：全双工交互模型**：不预设轮次——模型持续听持续说，不断决策继续/停顿/打断/调工具（Moshi、GPT-Live；交互性内建在模型而非外部 VAD 拼装）；还能委派后台推理、前台维持话头
- **两条独立轴线（关键澄清）**：语音通路端到端（音频进音频出）vs 认知架构端到端（实时交互与深度思考同模型共训）——完全可以通路端到端而认知上快慢分离
- **快慢思考分离（读写分离同构）**：交互表现与智能上限是两个维度——方案一快先答+慢再答（两实例独立思考可能前后矛盾：快模型建议购买、慢模型几秒后发现缺关键功能）；方案二快对话+慢建议（稳定但通信间接）；方案三思考表达统一（MGRD 基于声学特征思考 + MPS 双脑流水线——真边想边说但升级需整体重训）。**核心优势：直接承接慢模型迭代红利**（换后台模型不必重训实时系统——读写分离独立扩容同构）；实证 Pine AI 快慢分离 τ³-Voice 排第一——解耦不天然落后
- **更像人的 TTS**：过于流畅零停顿反而暴露机器身份——停顿和填充词是人类表达不确定性的信号；主 LLM 文本外输出控制标记（THINKING/EMO:happy/SPEED:0.8x）映射为停顿韵律笑声

### 38.1 · 级联延迟瀑布与流式压缩（作业①落点）
- **时间轴推演**（同一句 3s 语音）：A 串行——VAD 600→ASR 800→LLM 2000→TTS 首包 300，首响 3700ms/响应间隔 700ms；B 流式——转写藏进说话（500~3000）、思考 2400 抢跑（分支预测）、VAD 与生成重叠退出关键路径、首段 3200 出片、首包 3500 出声：首响 3500ms/响应间隔 500ms；两者总完成都 ~4900——**流式改的是首响不是总量**
- **推测执行的赌注**：B 首响（3500）早于 VAD 确认（3600）——赌确认一致；不一致则取消重算+收回已播（代价分支未推演）；语音越长重叠收益越大（ASR/VAD 占比下降、分段输出占比上升）
- **简化注**：延迟量级为教学典型值；纯时间轴推演（延迟结构是数字概念，时间轴即本体——不真 sleep，与 36.1 行为概念真跑的区分）

### 39 · Computer Use：GUI 自动化 Agent（闭环 + 定位）
- **感知-思考-行动闭环**：截图→模型看图出思考+动作→执行层真实点击→界面响应后再截图进下一轮。**看懂界面 ≠ 完成任务**：前者是一次截图问答（多模态理解），后者把理解和动作放进闭环——处理页面加载/状态变化/误操作/不可逆后果；真正难点是**动作后确认**：每步动作后重新确认现实是否仍符合计划（语音强调「何时开口」，Computer Use 强调「下一步点哪里」+「点完之后世界变了吗」）。后端类比：不是一次 RPC，而是读外部状态→决策→写回→再读的循环——写入前都要重读，不信任缓存旧状态
- **动作空间三类工具**（Anthropic 参考实现）：computer tool（鼠标移动/点击/拖拽/四向滚动/逐字输入每字符 12ms 模拟真人/组合键+截图+等待）、bash tool（**持久终端会话**——cd 过的目录下次还在，哨兵字符串判执行完）、str_replace_editor（字符串匹配式安全编辑，比全文件覆盖精确）。要点：**协议在 Harness 层不在模型层**——任何视觉模型都能驱动同一循环
- **Grounding 三路线**：SoM（分割模型切候选区域叠编号——纯视觉不依赖界面结构，桌面/游戏通用）/结构化元素索引（DOM/无障碍树枚举可交互元素+编号——browser-use：CDP 拿 DOM→检测→编号+边界框→文本清单，模型报 ID 系统换算中心坐标）/纯坐标预测（SeeClick/Claude——像人一样纯视觉，需大量 GUI 截图+元素位置配对数据专门训练）。**选择题永远比填空题好答**（把开放式预测坐标变成封闭式选编号）；代价：标注全量进上下文不省 token。选择逻辑：结构可得优先 DOM；不可得（Photoshop/Canvas/WebGL/游戏）用 SoM 或坐标预测
- **分辨率匹配坑**（坐标预测的隐藏坑）：模型对坐标的理解高度依赖训练分辨率（Claude 用 XGA/WXGA/FWXGA 三档），输入不匹配坐标系统性偏移（小地图量距离用到大地图）；解法：工具层**双向缩放**+按宽高比选档（硬塞 16:9 进 4:3 会压变形）——出入参值域与模型训练分布对齐，不对齐就做适配层
- **静止屏幕假设破灭 → AOI**（观察接口）：现实屏幕放视频/弹通知/播会议——离散快照看不见两帧之间的事；该重设计的是观察接口而非动作接口。三项技术：屏幕关键帧截图（小模型判断有意义变化才截）/音量门控语音转写（有声才调 ASR——让 Agent 听见）/用文字描述画面（一句话留上下文，原图清理后文字仍在——多模态交互历史压缩）
- **世界模型与推测执行**：人类先预测动作后果（符合预期继续、偏离才重新规划）而非点完才想；Agent 行动前预测「桌面接下来变成什么样」——重点不是生成逼真未来截图而是**可检查的状态差异**（如删除文件前在隔离虚拟桌面预测会不会弹不可逆确认框）。动机：准确率达人类水平 ≠ 实用（步骤明显多于人类、等待更长）
- **移动端的真问题是生态壁垒**：技术差异（动作空间变成无障碍服务 API+手势坐标语义）不是卡点；真正卡住的是商业模式冲突——传统应用变现靠流量与注意力（广告/推荐/冲动消费），Agent 直奔任务完成绕过这条链路，每次操作都在侵蚀平台商业根基——结构性利益冲突比 CAPTCHA 技术对抗更难解

### 39.1 · 结构化元素索引：清单长什么样
- **产出 browser-use 同款输入**：html.parser 枚举本地 HTML 样本可交互元素（a/button/input/select/textarea + onclick div）→「ID+tag+原因+文本+坐标」文本清单；标签内文本优先于 href/placeholder（人类看到的是文本）；<p> 不在清单——可交互判据生效
- **简化注**：静态解析拿不到 JS 动态渲染元素（生产用 CDP 连活页面拿实时 DOM）；真实边界框/中心坐标来自浏览器排版引擎（DOM.getBoxModel）非顺序推算

### 39.2 · 感知-思考-行动闭环（modal 陷阱）
- **闭环文本化**：界面渲染成结构化元素索引清单（39.1 同款——选择题优于填空题：模型只报编号），deepseek-chat 纯文本驱动（结构化索引恰好把视觉问题变成文本问题）；执行层是文本渲染的下载页状态机，每轮动态重新编号（=重新截图标注）
- **modal 陷阱实证「动作后确认」**：click 下载链接→弹出不可逆确认框（世界变了）→弹窗期间其余交互返回「⚠ 阻断」——外部系统不配合旧计划；实测 5 轮闭环：输入→搜索→点击→弹窗→确认→done（模型直接正确处理弹窗；先撞阻断再处理也算过——都体现动作后确认）
- **观察即下一轮感知**：执行反馈自带新界面 render（wait_for_ui 后再截图的同构）；验收看终态不看文案（downloaded == 目标文件 + done）

### 41 · W6 小结：共享骨架 + 五原语跨尺度复用
- **W6 在全书的位置**：第一章说过模型固定时提升 Agent 最主要的系统工程手段是扩展观察/动作空间——第 2-5 章扩的是这两个空间的**内容**（上下文/记忆/工具/代码），第 6 章扩的是**模态**（能否听说/看屏/驱动关节）与**时机**（世界推着来 vs Agent 拉着取）
- **统一控制骨架**：语音/CU/机器人本质是同一个循环跑在不同时间尺度：持续感知→判断状态与时机→选择回复或动作→输出进环境→观察反馈→继续/修正/重试/停止/重新规划——后端视角就是**读-判-写-验**闭环，区别只在每环实现深度
- **时间尺度决定架构**：异步事件秒-天（世界主动唤醒）/语音 10ms（边说边听可打断）/CU 亚秒-秒（两帧之间变化，动作后必须重确认）/机器人毫秒（传感器连续回流，动作分块可被抢占）——四个场景差六个数量级，但骨架同构
- **五原语**（跨场景复用，后端类比）：唤醒=MQ push 触发消费者/安全点=事务边界检查点（事件只能在这里被消费）/取消=中断信号+清理（Go ctx.Done()）/抢占=高优打断低优/快慢分离=C 端快响+后台深算。**同一原语不同尺度实现完全不同**——差异由环境变化速度与动作可逆性决定：变得越快、越不可逆，安全点越密集（事件驱动里是 LLM 一段推理结束或工具返回；机器人里是一小段预生成动作执行完毕）
- **时效与上限的权衡**：响应越快单步推理越浅——语音「说错再纠正」/CU「先点再看」/机器人「走一步看一步」各自化解；配套安全设计：动作分级（读宽松/写审批）、可逆操作优先、动作后状态确认、权限控制、安全停止
- **一句话收束**：模态与时机扩展的尽头不是三个领域三套技术，而是**同一个控制闭环 + 五个可替换原语**——掌握这个抽象，第七章评估体系好懂得多

18. asyncio ≠ 原生异步指什么？（应用层并发≠模型层异步——接口要求补齐工具结果才能继续时，仍需事件队列/句柄/兼容层；原生异步省兼容层但三检查仍是应用层责任）
19. 为什么专门讲语音？（说话≈打字 4 倍速且不占双手视线；语音 Agent 是长连接实时系统不是请求-响应——边听边想边说随时被打断；还有对外交互方向：代打电话）
20. 级联流水线的结构与代价？（VAD→ASR→LLM→TTS 串行，微服务同构可独立优化；延迟串行累积+接口丢副语言（情绪/犹豫/附和声））
21. 流式四手段？（ASR 边听边转/LLM 推测执行（分支预测：临时转录先想，不一致取消重算）/LLM 分段输出/TTS 增量合成——完全串行改边到边；流式听觉再进一步：声学事件标记感知犹豫打断）
22. Omni 与全双工差别？（都音频进出；Omni 按轮次靠 VAD（报号码的停顿仍会误判），全双工持续听说「该谁说话」是模型持续决策——可打断可重叠可委派后台）
23. 两条独立轴线？（语音通路端到端（音频进出）vs 认知架构端到端（实时交互与深度思考同模型）——可通路端到端而认知快慢分离）
24. 快慢三方案？（快先答+慢再答（独立思考可能矛盾）/快对话+慢建议（间接但稳定）/思考表达统一（MGRD+MPS 真边想边说，升级需重训））
25. 快慢分离的核心优势？（承接慢模型迭代红利——换后台模型不重训实时系统（读写分离同构）；Pine AI 快慢分离 τ³-Voice 排第一——解耦不天然落后）
26. 更像人的 TTS？（停顿和填充词是不确定性信号——过于流畅零停顿反而暴露机器；主 LLM 输出控制标记 THINKING/EMO/SPEED 映射停顿韵律）
27. 看懂界面与完成任务的差别？（前者一次截图问答（多模态理解）测答对没有；后者把理解和动作放进闭环——处理加载/状态变化/误操作/不可逆；难点是动作后确认：每步后重新确认现实仍符合计划）
28. 动作空间三类工具与关键要点？（computer/bash（持久会话+哨兵字符串）/str_replace_editor（字符串匹配安全编辑）；协议在 Harness 层不在模型层——任何视觉模型可驱动同一循环）
29. Grounding 三路线与选择逻辑？（SoM 纯视觉分割叠编号/DOM·无障碍树枚举编号/纯坐标预测需专门训练；选择题永远比填空题好答；结构可得优先 DOM，不可得用 SoM 或坐标预测）
30. 分辨率匹配坑与解法？（坐标理解高度依赖训练分辨率（Claude 三档 XGA/WXGA/FWXGA），不匹配系统性偏移；工具层双向缩放+按宽高比选档——出入参值域与训练分布对齐，不对齐做适配层）
31. 静止屏幕假设与 AOI 三技术？（屏幕放视频弹通知——离散快照看不见两帧之间的事；关键帧截图（有意义变化才截）/音量门控转写（有声才 ASR）/文字描述画面（多模态交互历史压缩）；该重设计的是观察接口而非动作接口）
32. 世界模型与推测执行？（人类先预测动作后果：符合预期继续偏离才重规划；Agent 行动前预测下一状态可检查的差异（删除前预测弹不可逆确认框）；准确率达人类 ≠ 实用（步骤多等待长））
33. 移动端的真问题？（技术差异（无障碍 API+手势）不是卡点；生态壁垒——Agent 直奔任务绕过流量变现链路，每次操作侵蚀平台商业根基；结构性利益冲突比 CAPTCHA 更难解）
34. 39.2 的 modal 陷阱演示什么？（点击后弹不可逆确认框+阻断其他交互——外部系统不配合旧计划；每轮重新 render 即重新截图：动作后确认现实，不信任缓存状态）
35. W6 在全书的位置？（第 2-5 章扩观察/动作空间的**内容**（上下文/记忆/工具/代码），第 6 章扩**模态**（听说/看屏/驱动关节）与**时机**（世界推 vs Agent 拉））
36. 统一控制骨架？（感知→判断→动作→反馈：持续感知→判断时机→选择回复或动作→输出进环境→观察反馈→继续/修正/重试/停止/重规划——读-判-写-验闭环，四场景只是每环实现深度不同）
37. 时间尺度与架构对应？（异步秒-天（世界唤醒）/语音 10ms（边说边听可打断）/CU 亚秒-秒（两帧之间变化动作后重确认）/机器人毫秒（连续回流动作分块可抢占）——差六个数量级但骨架同构）
38. 五原语的后端类比？（唤醒=MQ push/安全点=事务边界检查点/取消=ctx.Done()+清理/抢占=高优打断低优/快慢分离=C 端快响+后台深算）
39. 安全点密度由什么决定？（环境变化速度+动作可逆性——变得越快、越不可逆，安全点越密集：事件驱动推理段级（秒）vs 机器人动作分块（毫秒））
40. 时效与上限的张力与化解？（响应越快单步越浅；语音「说错再纠正」/CU「先点再看」/机器人「走一步看一步」；配套安全：动作分级/可逆优先/动作后确认/权限控制/安全停止）
41. 一句话收束 W6？（模态与时机扩展的尽头不是三套技术，而是同一控制闭环+五个可替换原语——掌握抽象第七章评估好懂）
