## 记忆卡

### 36 · 模态与触发时机：能力坐标系的两条新轴
- **比喻**：观察空间×动作空间 = API 的出入参 schema——入参类型越丰富能处理的问题越广，出参能力越强能触达的世界越大；模型是那个「处理函数」，**函数不改，改 signature 照样解锁新场景**（常见误区：以为能力提升只能靠换更强的模型——多数产品级提升来自扩展 I/O，像后端优化先改架构而不是先换机器）
- **前五章挂回坐标系**：上下文工程/记忆/RAG 扩观察空间的内容；工具/代码生成扩动作空间的内容——W6 沿「模态」「时机」两轴扩展
- **模态 = 形式维度**：观察从只读文本到语音/屏幕/物理传感器；动作从只输出 token 到发声/点击/驱动关节；类比接口协议升级（JSON 文本 → 音频流/图像帧/控制信号）——协议一变，编解码、带宽、时序全要跟着改（所以本章每种模态单独一天）
- **触发时机 = 节奏维度**：观察是主动取（轮询）还是世界推（事件驱动）；动作是回合内做完还是跨回合、可中断、可被抢占；类比轮询 vs Webhook/消息队列、同步 RPC vs 异步任务——前五章的 Agent 是同步接口（请求进来处理完才返回，期间不接新请求），本章改造成事件驱动的服务
- **为什么时机轴先走**：纯架构问题不涉及新 I/O——D37 异步的模态完全没变（还是文本），只变节奏；这是从回合制世界迈出的最小一步

### 36 · 核心论断：回合制是交互约定，不是环境性质
- **论断**：默认「用户说完 → Agent 想一段 → 答一句，期间世界静止」——这个前提自然到很少被当成假设写出来，但它只是早期工具调用接口的组织方式（提问后跟回答、工具结果补齐后才继续推理）；**环境是连续的、并发的，回合制只是给接口降了速**
- **为什么必须打破**：邮件在 Agent 思考时到达、用户在它说到一半时插话、页面在两次截图之间变了样、杯子在机械臂伸手途中被碰倒——真实世界不等人
- **两个常见误区**：① 把 API 的同步轮次当成物理限制——截至 2026 年 9 月 GPT-6 Astra 已支持原生异步工具调用和回合中途追加用户指令；② 以为代码里用了 asyncio 就具备原生异步能力——事件来源、工具生命周期、结果归属仍要应用层自己管理

### 36.1 · 两种世界观的最小现场（回合制 vs 事件驱动）
- **实证（同一确定性事件流：0.0 定时任务 / 0.2 新邮件 / 0.5 CI 失败 / 1.2 收尾）**：A 回合制——CI 延迟 0.5s（邮件回合 0.2~0.7s 把它压到 1.0s 才开始处理）、思考期间邮件堆积、总时长 1.5s；B 事件驱动——CI 延迟 0.0s（到达即抢占分块中的邮件处理）、摘要任务发起即挂句柄不阻塞、1.2s 收尾事件关闭、总时长 1.2s——**同一世界两种命运**
- **B 版三个机制（D37 的伏笔）**：队列唤醒（q.get 阻塞等待不忙轮询）+ 高紧急抢占（分块执行、块间让位——课件机器人档「动作分块·可被抢占」的最小形态）+ 动作跨回合（发起挂句柄，靠收尾事件 close——任务句柄雏形）
- **简化注**：抢占用「块间查队列」模拟（sleep 不可中断）——生产用 asyncio.cancel/线程中断；事件源生产上是消息队列/webhook 非脚本线程

### 37 · 异步与事件驱动：当世界主动找上门
- **比喻**：同步 Agent 是只会排队的柜台（处理完一个才叫下一个——要么等后台任务才能对话，要么等对话结束才能接新事件）；异步 Agent 是灵活的秘书（多待办按紧急程度切换，做到一半可暂停）——BIO→NIO 的切换；把所有输入（用户消息/工具返回/外部回调/定时触发）统一建模为事件流，push 取代轮询
- **三类事件触发工具**：set_timer（一次性「下周一十点致电」/循环「每小时巡检」——对方不推送的服务只能定时反复查）、monitor_shell（长命令监控新增输出或关键词——不能烧 token 盯着看也不能跑完才发现卡死）、connect_channel（邮件/API 回调/IM 实时推送——PineClaw 心跳轮询早等凉了）；设计要点：触发条件带过滤（无关事件不唤醒）、载荷自带上下文（减少二次查询）
- **结构化事件四维**（来源/渠道/内容/上下文）——统一 schema 后三策略才有统一前提（Kafka 统一信封）；**来源维度是注入防线**：只有来源清晰才不会把工具结果里藏的指令当成用户指令
- **三策略（紧急度路由）**：取消式（紧急：提前制造安全点——取消流式→清空队列→全部事件追加→立即重估）、队列式（常规：攒到安全点批量追加省往返，如等搜索时用户补「只看最近一个月」）、并行式（独立轻量：旁路小会话即答，结果标记后归档主轨迹）；**路由器用轻量分类 LLM 非硬编码**（37.1 实证）
- **占位符规则**：打断时为未完成工具生成占位 ToolMessage 维持配对合法，**不伪造成功**；「收到停止不撤销已发生的动作」——被打断的查询后台跑完迟到（已提交事务不自动回滚），结果仍归属
- **任务句柄 initiate_xxx**：启动与完成解耦——工具命名就是给模型的 API 文档（initiate 前缀暗示「发起而非完成」），立即返回 task_id，结果以事件到达；submit/job_id/Future 同构
- **误区与边界**：asyncio ≠ 原生异步（应用层并发≠模型层异步——事件来源/工具生命周期/结果归属仍要应用层管）；GPT-6 Astra 已支持原生异步工具调用+回合中途引导，但三检查（结果归属/恢复控制/多条更新综合）仍是应用层责任
- **沟通工具与虚拟身份（速览）**：专门工具发消息（双方随时互发/按紧急度推送=活人感，通知即召回）；独立虚拟身份+虚拟电脑隔离（最小权限 service account 而非共享 root）；必须本人登录走 VNC 远程桌面 HITL（亲眼看到 Agent 在做什么）

### 37.1 / 37.2 · 路由与兼容实验
- **37.1（关键词 5/7 vs LLM 语义 6/7）**：棺材钉一（「先别继续了，马上」无「停」字，关键词版误入队）语义路由判对；棺材钉二（「别停在半路，继续跑完」含「停」）模型判 cancel 且理由自洽（「立即处理继续指令」）——语义边界如实呈现（22.3 三跑摇摆同款）
- **37.2 不编造双份实证**：幕一（2 个并行 search 被打断→逐个占位符→模型「没有返回任何结果……我不会凭记忆硬写」→迟到结果恢复总结）；幕二（3 个并行 initiate 拿动态句柄 t1/t2/t3→「都还在运行中，我不能凭记忆先给结论」→结果事件到达综合）——可靠性三检查之首（结果归属）的正面证据
- **首跑翻车**：deepseek 常并行发多个 tool_call，只配一个 ToolMessage → 下一轮 invoke 400（「配对规约是硬约束」）；修为 drain 逐个配对

1. 观察空间/动作空间各是什么？为什么是能力坐标系？（Agent 能看到什么/能做什么；底层模型固定时，扩展两空间是提升表现最主要的系统工程手段——前五章扩内容，本章扩模态与时机两轴）
2. 前五章的工作挂在坐标系哪里？（上下文工程/记忆/RAG 扩观察空间的内容；工具/代码生成扩动作空间的内容）
3. 模态是什么维度？触发时机是什么维度？（形式——观察从文本到语音/屏幕/传感器，动作从 token 到发声/点击/驱动关节；节奏——主动取 vs 世界推、回合内做完 vs 跨回合可中断可抢占）
4. 为什么时机轴先走？（纯架构问题不涉及新 I/O——D37 异步模态没变还是文本只变节奏，是迈出回合制的最小一步）
5. 核心论断是什么？为什么必须打破回合制？（回合制是交互约定不是环境性质——只是早期工具调用接口的组织方式；真实世界连续并发不等人：邮件思考时到达、用户说到一半插话、页面两次截图间变样）
6. 两个常见误区？（①把 API 同步轮次当物理限制——GPT-6 Astra 已支持原生异步工具调用+回合中途追加指令；②用 asyncio ≠ 原生异步——事件来源/工具生命周期/结果归属仍要应用层管理）
7. 响应时间尺度四档与各自闭环要求？（秒-天异步：事件唤醒动作跨回合；10ms-1s 语音：边说边听可打断；亚秒-秒 Computer Use：动作后重新确认现实；毫秒机器人：动作分块可抢占——每档是不同架构学科）
8. 36.1 实验的对照结论？（同一事件流：A 回合制 CI 延迟 0.5s（邮件回合压着）+ 堆积；B 事件驱动 CI 延迟 0.0s（抢占分块任务）+ 摘要挂句柄跨回合收尾——同一世界两种命运）
9. 两个事件同时到达怎么办？（紧急度×可逆性：高紧急抢占、同级并行（挂句柄）、低级排队；不可逆操作不抢占保原子性；同资源写冲突串行——中断优先级+资源锁的合体）
10. 事件驱动版的三个机制与生产差距？（队列唤醒/高紧急抢占（分块执行块间让位）/动作跨回合（句柄+收尾事件）；差距：抢占用块间查队列模拟（生产 asyncio.cancel），事件源是脚本线程（生产消息队列/webhook））
11. 为什么需要异步？（柜台→秘书：长任务不阻塞交互/优先级动态判断/打断后自然恢复——BIO→NIO；把所有输入统一建模为事件流，push 取代轮询）
12. 三类事件触发工具？（set_timer 一次性/循环（不推送的服务只能定时反复查）；monitor_shell 监控新增输出/关键词；connect_channel 邮件/回调/IM 推送；触发带过滤、载荷自带上下文）
13. 结构化事件四维与防线作用？（来源/渠道/内容/上下文；来源清晰才不把工具结果里藏的指令当用户指令——统一 schema 是三策略的前提）
14. 三策略与判定方式？（取消式=紧急制造安全点重估；队列式=常规攒批省往返；并行式=独立轻量旁路即答；路由用轻量分类 LLM 非硬编码）
15. 占位符规则？（打断时为未完成工具生成占位 ToolMessage 维持配对合法不伪造成功；停止不撤销已发生动作——迟到结果仍归属）
16. initiate_xxx 为什么这样命名？（工具命名即 API 文档——initiate 暗示发起≠完成，立即返回句柄，结果以事件到达；submit/job_id 同构）
17. 37.2 的不编造实证？（幕一「没有返回任何结果……不会凭记忆硬写」/幕二「都还在运行中，不能凭记忆先给结论」——结果归属的正面证据）
18. asyncio ≠ 原生异步指什么？（应用层并发≠模型层异步——接口要求补齐工具结果才能继续时，仍需事件队列/句柄/兼容层；原生异步省兼容层但三检查仍是应用层责任）
