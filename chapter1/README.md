## 记忆卡

### 01 · 最小 Agent（规则版）
- **核心**：大脑决策、手脚执行、观察写回——7 行核心逻辑就是 Agent 的全部骨架
- **代码落点**：`if "tool" not in resp: return` ——无动作 = 任务完成
- **自测钩子**：把 `messages.append` 那行删掉会怎样？（模型看不到工具结果，反复调用同一工具）

### 02 · 接入真实 LLM
- **核心**：规则函数 → ChatOpenAI + `@tool` + `bind_tools`，**骨架不变**
- **要点**：`@tool` 从类型注解 + docstring 生成 JSON Schema——工具定义与 schema 合一
- **对照 01**：变的只有 llm() 内部；agent_loop 一行不动——好架构的标志

### 03 · Harness 五要素
- **比喻**：马具（Harness 原意）——不是限制马跑，而是把力量引导成可靠执行
- **五要素口诀**：上下文管理（决策点信息充分）· 工具接口（观察与行动的手段）· **约束**（默认全关、显式放行）· **验证**（只看结构化字段，别 parse 文案）· **纠正**（重试 + 熔断转人工）
- **数字钩子**：Terminal Bench 2.0 上 LangChain 改 Harness 不换模型，52.8% → 66.5%
- **边界**：工具注册表属 Harness；被调用的订单服务属 Environment——"随行动变化的外部状态"才是判据，不看部署位置

### 04 · 提议者-审核者
- **比喻**：没人允许自己 approve 自己的 PR
- **成立前提**：自审不可靠——同一上下文里的模型难发现自己认知盲区，也难察觉自己被注入
- **隔离性**：审核者只看**产物**（渲染结果/测试输出/调用参数），不看提议者的推理过程
- **配套**：只增不改的 AuditLog（链式指纹 prev）——可缓存、可重放、可审计
- **落点**：第 3 章知识更新、第 4 章事前审批、第 7 章评估

### 05 · 双角色 LLM 版
- **核心**：隔离性的落地手段——两个**独立 LLM 实例**，各自 system prompt，不共享上下文
- **对照 04**：04 用规则函数演示"只看产物"；05 证明隔离在真实模型上同样成立

### 06 · ReAct 循环
- **口诀**：想 → 做 → 看 → 再想；**"手脚做了" ≠ "大脑知道了"**（观察必须写回）
- **比喻**：轨迹 = append-only 请求日志表，每轮全量读出拼 prompt；max_turns = 熔断保险丝（不是超时器）
- **断环实验**：工具持续失败 + 强制重试 → max_turns 熔断（纠正机制在兜底）

### 07 · W1 一页图谱
- 三件套 → Harness → 五模式，ASCII 图一页串起来；五章学完回头看，这张图就是全书地图

## 五个设计模式（全书公共词汇表）

| 模式 | 后端熟语 | 一句话 | 后续落点 |
| --- | --- | --- | --- |
| 提议者-审核者 | 无人自批 PR | 产出与评判分两个不共享上下文的角色 | 第 3 章知识更新、第 7 章评估 |
| 渐进式披露 | 分页/懒加载 | 先给目录，按需加载细节 | 第 2 章 Skills、第 4 章工具动态加载 |

| 最小 diff+可回滚 | 小步发布 | 改动小、记来源、能撤回 | 第 5 章 Coding Agent |

## 自测（遮住括号自测）

1. 01 里 `"tool" not in resp` 为什么是终止条件？（无动作 = 模型认为任务完成）
2. 03 的 verify 为什么只读 `code` 字段不解析文本？（自由文本可能已被提示注入操纵——看返回码，别 parse 文案）
3. 04 的审核者为什么"只看产物"？（隔离性：看产物能发现产出问题；看推理过程会被提议者的自我合理化带偏）
4. 06 的轨迹为什么 append-only？（每轮全量重发需要完整历史；回头改历史=篡改审计日志）
5. 五模式里哪个直接服务于 KV Cache？（只增不改——前缀不动，缓存才能命中；第 2 章展开）
